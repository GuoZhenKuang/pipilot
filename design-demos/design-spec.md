# Pi Mobile UI 重设计 · 设计 Spec（三版共同输入）

> 2026-08-30 固化。三个设计方向独立工作，只看本文件。

## 1. 产品是什么

**Pi Mobile** —— Pi 编程智能体的 Android 客户端。Pi（AI 编程智能体）跑在用户的笔记本上，本 App 让开发者**离开电脑后用手机实时掌控编程会话**：查看流式输出、调整方向（steer）、追加消息（follow-up）、查看工具调用与代码 diff、管理多个主机与工作区。连接链路：Android → WebSocket Bridge（Tailscale）→ `pi --mode rpc`。

一句话气质定位：**「随身编程会话驾驶舱」，不是聊天软件。**

## 2. 受众与场景

- 受众：开发者（作者自用 + 开源社区），对终端、代码、遥测读数有天然亲和。
- 场景：手机单手/双手操作，屏幕 6.1-6.7 英寸；光线环境多样（深夜被窝调会话、户外强光下瞄一眼进度）→ 深浅两读法都要成立，原型至少做一种做到极致。
- 情感基调：冷静、可靠、掌控感、专业。紧张时刻（会话出错、需要中止）信息要一眼可辨。

## 3. 信息架构（5 屏，全中文文案）

1. **主机**（引导 + 管理）：首次引导卡「连接你的电脑」（Bridge + Tailscale + `pnpm pair` 扫码配对）；主机卡：名称、endpoint、TLS/令牌状态、连接诊断（模型、工作目录）、测试/编辑/删除。
2. **会话驾驶舱**（核心调度台）：主机健康状态行、收敛后的过滤（置顶/活动中/全部 + 搜索）、会话卡（标题、工作区、模型、消息数、相对时间、活动状态灯、preview 摘要、快速操作：打开/快速回复/更多）、置顶分组。
3. **聊天**（绝对主角，120% 用力）：头部（会话名 + 连接状态 + 同步/更多）、模型·思考级别·上下文读数（42% · 12.3K/200K · $0.084）、时间线（用户消息右对齐、Pi 回复含可折叠思考块、工具组「使用了 3 个工具 · 已完成」：读取/编辑(带 diff)/执行命令、代码块语法高亮）、运行进度（工作中 · 正在运行工具 · 01:24）、输入区（steer「调整方向」/「追加消息」模式 chip、附件、斜杠命令、发送/停止）。
4. **终端/详情**（二选一或并置）：bash 面板（命令输入、历史、输出、退出码 0 绿）；或会话统计（输入/输出 token、消息数、总费用、交接摘要）。
5. **设置**：连接状态、自动化（自动压缩/自动重试）、传输方式（自动/WebSocket/SSE）、外观（主题三态）、发送模式、版本号。

## 5. 输出格式（硬约束）

- **纯 HTML + CSS + 原生 JS 单文件**（用户明确要求「纯HTML」；禁止 React/Babel/构建工具）。唯一允许的外链：Google Fonts `<link>`（必须写好系统字体回退栈，断网可看）。
- 页面 = **展示画布 + 平铺 Android 手机**：深色中性画布（#101014 级，不要纯黑），顶部统一标注条「Pi Mobile UI 重设计 · 方向 N · <风格名> · 一句话定位」，下方水平排列 5 台手机（允许 wrap）。每台手机上方一个小标注（屏幕名）。
- **设备框几何（Pixel 8 风格，必须精确遵循）**：外壳 padding 10px、bg #1a1a1a、圆角 44px、外圈 ring 2px #2a2a2a、大投影；屏幕 412×892px、圆角 36px、overflow hidden；状态栏高 32px（左时间 `22:17`，右侧信号/WiFi/电池内联 SVG）；打孔相机 14px 圆、top 10px 水平居中；内容区 top 32px ~ bottom 24px；底部手势条 100×4px 圆角、居中。
- 每台手机内至少 **2 处真实可交互**（点击有效、无 JS 报错）：折叠/展开思考块与工具卡、过滤 chip 真过滤列表、模式 chip 切换、开关切换、终端可输入回显等，任选。
- 可读性硬底线：正文 ≥14px、标签/注释 ≥12px、正文对比度 ≥4.5:1。留白必须是有视觉锚点的构图，不是内容缺席。

## 6. 反 AI slop（硬禁区）

- 禁：紫渐变、emoji 当图标、圆角卡片+左彩色 border accent、GitHub-dark 偷懒解（#0D1117 均匀深蓝底+通用青紫霓虹 glow）、Lorem ipsum、装饰性 icon 每标题一个。
- 密度要求：这是**高密度型**产品（卖点是掌控/遥测）——每屏 ≥3 处**有内容的**差异化信息（读数、状态、路径、token、费用、退出码……），加的是有内容的密度，不是装饰。
- 所有视觉用 CSS/SVG 精确绘制；无照片需求（工具型 UI）。

## 7. 三个方向（各 subagent 只做自己这版）

- **方向一 · 包豪斯几何 Bauhaus Geometric**（秒数轮盘 49→10 号风格，还原度 90%）：包豪斯红 #E63946 / 黄 #FFB703 / 蓝 #0077B6 + 黑白，几何无衬线（Poppins/Manrope 栈），圆/三角/方几何单元做状态标记与插画，模块化拼图栅格、对齐、扁平无渐变。浅色纸白底。骨架特征：**几何模块分区构图**。
- **方向二 · Linear 驾驶舱**（现实参照：linear.app，"The Linear Look" 已核实）：近黑 #08090A 底、品牌紫 #5E6AD2、去饱和低光、Inter（负字距 display）+ JetBrains Mono、发丝分割线（rgba 白 6-8%）、极精细灰阶层级、4px 基线网格、严格排印层级。骨架特征：**深色单列信息流 + 精细读数轨**。（注：Linear 是真实品牌本身走深色+品牌紫，合法；但 glow 必须极克制，靠灰阶与排印立住，不是靠发光。）
- **方向三 · Teenage Engineering 控制面板**（最佳设计师：Teenage Engineering 设计哲学）：暖灰米白金属面板 #E8E4DC 系 + 黑 + 信号橙 #FF4B00 accent，硬边按钮/实体键隐喻、等宽字读数（IBM Plex Mono）、密集但秩序的功能分区、产品编号标签（如「PM-01」「CH·03」）、电平表式进度。骨架特征：**顶部设备读数带 + 分区控制面板**。

## 8. 结构理顺（三版共同目标）

- 解决现有「双标题」问题：一屏一顶栏。
- 收敛现有泛滥的 FilterChip（驾驶舱原有 8+ 个 chip）。
- 卡片套卡片 → 清晰的两级层次以内。
- 状态（连接/活动/错误）用统一语义色与形状语言表达。

## 9. form 推导（每版交付时回答）

每版在标注条里用一句话写明「form 来自内容的哪里」（视觉母题）：
- 方向一候选母题：几何模块 = 功能分区（机器时代的功能美学）
- 方向二候选母题：会话流 = 遥测时间线（键盘驱动驾驶舱）
- 方向三候选母题：手机 = 一台便携控制设备（硬件面板化）
