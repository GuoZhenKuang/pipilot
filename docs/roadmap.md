## 继承的架构约束（红线）

以下约束从历史计划整体继承，任何阶段都不得突破：

- 保持「Android → 经过认证的 WebSocket Bridge → 每个工作目录一个隔离的 `pi --mode rpc` 进程」架构。
- 本地保存的动作只使用 `SessionKey(hostProfileId, sessionId)`；对外链接只使用不透明共享引用；普通界面不暴露绝对路径/完整 cwd/令牌/会话文件元数据。
- 只使用有文档记载的 Pi RPC 命令；内部扩展仅用于会话树导航。

## 各阶段要点

### R1 引导与文档（含原 018 的可用性目标）

- Bridge 一键启动：提供 Windows 启动脚本（校验 Node/Pi、生成 `.env` 模板、启动服务、打印配对二维码）。
- 配对流程容错：二维码版本/令牌失效的明确提示；TLS 开关、端口、Headscale 域名差异内嵌到 App 引导页与文档。
- `docs/` 核心文档（architecture / codebase / testing / onboarding / dependency-matrix）汉化，README 链接同步。
- 原 018 中的「API 37/Node GO 决策后的本地链路发现」暂缓，除非 R1 交付后仍有明确痛点。

### R2 后台连续性与通知（原 014）

- 一个 App 级会话控制器；前台服务展示当前运行状态。
- opt-in 的尽力而为前台连续性 + 当前会话小组件。
- 明确边界：不做云推送；force-stop/系统杀进程后不承诺送达；通知内容隐私脱敏（不含会话内容）。

### R3 会话组织与谱系（原 015）

- 将已解析的精确父引用映射为可展示的分叉谱系，不改变活动 `get_tree` 语义、不从路径/元数据猜测。
- 会话按项目（工作目录分组）组织展示，置顶/隐藏能力保持本地。

### R4 语音输入与输入区无障碍（原 016）

- 接入系统级听写（平台输入），明确披露；插入为草稿、绝不自动发送；不上传音频。
- 输入区与关键操作的无障碍标注补齐。

### R5 多工作区运行时仪表盘（原 017）

- 监控型多主机面板：每台启用主机一条监控传输、有界并发、不透明的工作区引用。
- 明确的 GO/INCONCLUSIVE 判定阈值，不阻塞既有会话功能。

### R6 长期维护项

- 文案资源化：若需要英文版本，将硬编码中文文案迁移到资源体系（当前产品默认中文，暂缓）。
- 上游 Pi 版本策略：维护「已验证版本矩阵」，Pi 升级后跑 RPC 兼容夹具再发版。
